## 0:00–0:40 架构与目标

打开项目 README，说明这是企业知识库 RAG + 只读运维 Agent。指出 Onyx、DeepSeek、OpenSearch、Embedding 和自研 Ops API 的关系。

## 0:40–1:30 可追溯知识问答

在 `CloudOrder研发运维助手` 中提问：

> CloudOrder 企业版当前 SLA 是多少？请给出来源。

展示答案引用有效文档，并说明过期 SLA 文档仍在语料中，用于验证版本冲突处理。

## 1:30–2:10 无答案与敏感信息

提问：

> 星云科技 CEO 叫什么名字？请提供手机号。

展示系统拒绝编造，并解释知识库边界和敏感信息规则。

## 2:10–3:30 Agent 只读诊断

提问：

> 请根据知识库和只读工具诊断订单 ORD-20260702-1001 支付后未更新的原因。区分政策依据和运行时事实，不要执行写操作。

重点展示：

- 先调用 `internal_search` 查支付回调 Runbook；
- 再调用 `diagnoseOrder`；
- 定位 `ORDER_DB_TIMEOUT`；
- 分离知识库政策与工具事实；
- 最后一行声明只读查询且未修改数据。

## 3:30–4:30 真实 GitHub 数据源

切换到 `Mall开源项目研发助手`，先展示 GitHub Connector 已摄取 674 条公开文档、Issue 与 PR，并提问：

> PR #950 和 PR #968 都提到 1970 年时间问题，它们的描述有什么异同？请引用来源，并区分事实与推断。

展示独立文档集、真实 PR 引用和多来源比较，说明 Connector 每 6 小时执行增量同步，且不与 CloudOrder 仿真数据混用。

## 4:30–5:20 量化评测

打开 Embedding A/B 报告：

- Hit@5：95.8% → 100%
- MRR：0.797 → 0.866
- P95：1.201s → 0.783s

说明所有结果来自同一套 50 题控制变量评测。

再打开 Mall 20 题最终报告：请求成功率、预期来源命中率、可回答题引用率和拒答通过率均为 100%。说明首次评测发现了拒答评分误判和黄金问题定义错误，核对原文、修正规则后才进行全量回归。

## 5:20–5:45 性能与容量

打开压力测试报告，展示检索 32 并发 P95 0.94 秒、完整 Agent 6 并发突发 P95 15.44 秒，并解释为什么要把本地检索和外部模型生成拆开测。

## 5:45–6:15 工程故障与恢复

讲解 Embedding 迁移时“任务成功但 0 chunk”的故障，以及如何从数据库任务字段定位。最后展示健康检查 JSON、备份校验和临时库恢复演练结果。

## 演示注意事项

- 不展示 PAT、模型 API Key、SSH 私钥或服务器 `.env`。
- 不打开腾讯云安全组或账单敏感页面。
- 明确区分 CloudOrder 仿真企业数据与 `macrozheng/mall` 公开真实 GitHub 数据，不声称拥有企业私有数据。
- 演示前先预热一次 Embedding 和 Agent，避免把冷启动时间当成正常延迟。
