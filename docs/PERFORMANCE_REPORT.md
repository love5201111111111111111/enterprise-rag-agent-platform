# Onyx RAG/Agent 性能与压力测试报告

测试时间：2026-07-03  
环境：腾讯云 CVM，8 vCPU、32 GiB 内存、200 GiB SSD、5 Mbps；Onyx v4.2.2 Standard；Mall GitHub 知识库 674 条文档、900 个检索分块。

## 测试目标

本次测试把本地检索和完整 Agent 分开，避免将 DeepSeek 上游生成延迟误判为服务器检索性能：

1. **Retrieval**：请求 Onyx Search API，覆盖 API、查询处理和 OpenSearch 检索。
2. **Agent**：覆盖检索、Agent 编排、DeepSeek 生成和引用组装。
3. **资源采样**：测试期间通过 SSH 采集宿主机内存与各 Docker 容器 CPU/内存峰值。

所有请求均通过 SSH 隧道访问 `127.0.0.1:8088`。测试采用短时阶梯负载与突发负载，不执行破坏性极限测试和长时间稳定性测试。

|---|---:|---:|---:|---:|---:|---:|
| 单并发 | 1 | 6 | 100% | 0.42s | 0.44s | 144.08 RPM |
| 双并发 | 2 | 6 | 100% | 0.26s | 0.31s | 438.20 RPM |
| 四并发 | 4 | 6 | 100% | 0.25s | 0.28s | 679.41 RPM |
| 突发 | 8 | 8 | 100% | 0.32s | 0.34s | 1398.70 RPM |

### 高并发短时测试

| 场景 | 并发 | 请求数 | 成功率 | P50 | P95 | P99 | 吞吐量 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 高并发 | 16 | 32 | 100% | 0.55s | 0.67s | 0.70s | 1672.91 RPM |
| 高并发 | 32 | 32 | 100% | 0.91s | 0.94s | 0.96s | 1981.99 RPM |

32 并发时 OpenSearch 峰值约 144.28% CPU、API Server 约 99.83% CPU。Docker CPU 百分比按单核计，100% 约等于占满一个 CPU 核；宿主机有 8 vCPU，因此尚未达到整机 CPU 饱和。最低可用内存约 21.33 GiB。

## 完整 Agent 结果

| 场景 | 并发 | 请求数 | 成功率 | P50 | P95 | 吞吐量 |
|---|---:|---:|---:|---:|---:|---:|
| 单并发 | 1 | 4 | 100% | 10.78s | 13.70s | 5.31 RPM |
| 双并发 | 2 | 4 | 100% | 11.48s | 14.09s | 10.45 RPM |
| 四并发 | 4 | 4 | 100% | 12.10s | 12.35s | 19.42 RPM |
| 突发 | 6 | 6 | 100% | 13.94s | 15.44s | 23.32 RPM |

- 18/18 正式请求成功，未出现 HTTP 错误、超时或上游限流。
- 18/18 回答保留来源引用。
- 最低可用内存约 21.31 GiB，最高已用内存约 8.52 GiB。
- 容器峰值：Inference Model Server 约 70.77% CPU，API Server 约 42.08%，OpenSearch 约 28.32%。

## 结论

1. 本地检索链路不是当前主要瓶颈：在已测试的 32 并发下成功率 100%，P95 仍低于 1 秒。
2. 完整 Agent 延迟主要来自生成和编排链路：单并发至 6 并发的 P95 在 12.35～15.44 秒范围，明显高于检索延迟。
3. 当前开发实例内存余量充足；继续提升并发时应优先观察 API Server、OpenSearch、模型供应商限流和请求队列，而不是盲目扩充内存。
4. 基于本次短时测试，建议单实例先采用 **4 个并发交互请求、允许 6 个短时突发** 的保守运行上限；超过上限进入有界队列，避免把开发测试结果直接当作生产承诺。

## 工程建议

- 在 API 网关增加租户级速率限制和最大并发控制，超过阈值返回 429 或进入有界队列。
- 对相同检索查询和稳定知识答案设置短 TTL 缓存，减少重复调用生成模型。
- 保留流式输出，降低用户感知的首 Token 等待时间；单独监控 TTFT 和完整响应时间。
- 持续监控 API Server、OpenSearch、外部模型 429/5xx、队列长度和 Token 成本。
- 真正上线前再执行固定成本预算下的 30～60 分钟稳定性测试，并验证水平扩容、熔断和降级策略。

## 适用边界

本报告是单机开发环境的短时容量验证，不是生产 SLA 或最大容量证明。公开 GitHub 语料规模、请求问题长度、模型响应长度、DeepSeek 配额和公网条件都会影响结果。
